# 引导式诊断 RAG 重设计规格

## 背景与问题

当前 `DiagnosisTab` 只把四步问卷结果交给本地 `DiagnosticEngine`，页面没有复用自由问答的 SQLite 检索和端侧/云端 RAG 链路。现有交互还存在几个问题：身体酸痛字段没有参与规则匹配；最后一题选择任意一个症状就立即完成，无法表达多个症状；完成后选项仍可点击；没有上一步和修改答案。

## 目标

1. 将诊断流程改为“问卷采集 → 症状摘要 → SQLite 证据检索 → 云端/端侧 RAG 合成 → 原文降级”的完整链路。
2. 问答页和诊断页共享同一个推理会话，避免重复解析/加载 GGUF 模型，并让模式切换立即同时影响两页。
3. 让问卷具备明确的编辑、加载、结果和重置状态；最后一题支持同时记录口渴和发热。
4. 保留 `DiagnosticEngine` 作为可解释规则提示和单元测试基线，但不再把它的字符串直接当成诊断页面最终答案。
5. 更新 README，准确描述诊断的 AI 数据流、降级策略、测试和面试演示方式。

## 设计

### 共享推理会话

新增 `InferenceSession`，由 `HomePage` 创建和销毁，持有：

- 当前 `AppDatabase`；
- 当前 `QaService`；
- 可选 `LlmService` 和 `RagSynthesizer`；
- 推理模式切换、端侧模型加载状态和接线代数。

`QaTab` 和 `DiagnosisTab` 都只消费会话提供的 `QaService`，不再各自解析模型。会话在模式切换时先串行释放旧端侧模型，再构建新服务；没有任何模型/云端通道时提供检索-only 服务。

### QA 查询接口

扩展 `QaService.answer`，允许调用方分别传入：

- `query`：展示给模型的完整问题和上下文；
- `retrievalQuery`：用于意图识别、关键词拆分和 SQLite 检索的短症状词串。

默认 `retrievalQuery` 仍等于 `query`，保证现有自由问答行为不变。诊断服务使用短关键词检索、完整摘要交给 RAG，检索证据为空时沿用原有“资料中未找到”语义。

### DiagnosisService

新增服务接受 `QaService` 和 `SymptomInput`，负责：

1. 将选择的寒热、汗出、颈项痛、身体酸痛、口渴、发热整理为稳定顺序的关键词和可读摘要；未知/跳过项不进入检索词。
2. 调用 `DiagnosticEngine.evaluate` 得到候选规则提示，仅作为“规则线索”附加到 prompt，不作为最终结论。
3. 生成安全约束明确的诊断问题：只基于检索资料回答、指出证据不足、显示出处、内容仅供学习参考且不构成医疗建议。
4. 调用 `QaService.answer(query: ..., retrievalQuery: ...)`，返回回答、来源、channel 和 channelNote。

### 问卷状态机

`DiagnosisTab` 状态包括：

- `editing`：当前题目和已选答案；
- `submitting`：提交诊断请求，禁用重复点击并显示加载；
- `result`：隐藏题目选项，展示回答、通道标签、来源和重新编辑/重新开始按钮；
- `error`：数据库不可用或服务异常时展示可恢复提示。

问卷仍为四个主题步骤，但最后一步使用可切换的口渴/发热选项和显式“完成辨证”按钮，允许两者同时选择。前 3 步保留单选并自动进入下一步；所有步骤提供“上一步”，回退时保留答案并允许修改。重新编辑回到最后一步或当前步骤，重新提交会覆盖旧结果。

### 规则基线

`DiagnosticEngine` 的太阳伤寒规则使用“恶寒 + 无汗 + 颈项强痛或身体酸痛”，修复 UI 已收集字段未生效的问题；太阳中风仍要求“恶风 + 有汗 + 颈项强痛”。规则结果只作为 prompt 中的候选线索，不绕过 QA/RAG 链路。

## 错误与降级

- 数据库为空或检索异常：沿用 `QaService` 的错误文本，不崩溃。
- 无模型/云端配置：返回命中的知识库原文，channel 为 `retrieval`。
- RAG 空输出/异常：返回检索原文，并保留来源。
- 诊断请求期间重复点击：被状态机拒绝；请求完成后只接受当前请求令牌的结果。
- 无任何症状：不发起请求，直接提示需要至少一个症状。

## 验证标准

- 服务测试验证诊断摘要、检索词与完整 prompt 分离、规则线索注入、检索 fallback、端侧/云端 channel 传递。
- 页面测试验证四步推进、最后一步多选、上一步修改、加载态禁用、结果态隐藏选项、重新编辑和重新开始。
- 现有自由问答、RAG、规则和 widget 测试保持通过。
- README 描述新的诊断数据流和运行/测试命令，不承诺医学准确率或临床效果。

## 非目标

- 不引入新的医学知识库或未经验证的诊断规则。
- 不让模型输出替代医生诊断、处方或治疗建议。
- 不改变 SQLite schema、端侧模型格式或云端 API 协议。
